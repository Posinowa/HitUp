# Firebase Setup & Local Developer Guide

**STATUS: APPROVED guidance for HIT-009**

This document explains how Firebase is configured in HitUp, how client configuration is managed across environments, and how local developers configure their workstations.

---

HitUp uses **Firebase** as its sole managed backend (Authentication, Firestore, Analytics, Crashlytics). There is no custom server, no Cloud Functions, and no custom backend.

## 2. Configuration Strategy: Zero-Config in Git

To keep repository governance clean and adhere to repository policies, platform-specific client configuration files are managed as follows:

| File | Location | Repository Status | Purpose |
|---|---|---|---|
| `google-services.json` | `android/app/` | **Git-ignored** | Required by the Android Google Services Gradle plugin at compile time. |
| `GoogleService-Info.plist` | `ios/Runner/` | Committed (placeholder/client) | iOS configuration bundle. |
| `firebase_options.dart` | `lib/` | Committed | Dart cross-platform configuration generated by FlutterFire CLI. |
| `firebase.json` | Project root | Committed | Tooling & emulator configuration for FlutterFire and Firestore rules. |

### How CI Handles Android Builds
In GitHub Actions CI (`flutter_ci.yml` and `release_validation.yml`), the Android build jobs inject `google-services.json` automatically from the encrypted repository secret:
* **Secret Name:** `GOOGLE_SERVICES_JSON_BASE64`
* Before `flutter build apk` or `flutter build appbundle`, CI decodes this secret into `android/app/google-services.json`.

## 3. Local Developer Setup (Fresh Clone)

If you clone the repository freshly and attempt to build the Android app, Gradle will notify you that `google-services.json` is missing:

```text
File google-services.json is missing. The Google Services Plugin cannot function without it.
```

Follow these steps to configure your local environment:

### Step 1: Obtain `google-services.json`
1. Ask the project lead or owner for access to the `hitup-691be` Firebase project.
2. Open the [Firebase Console](https://console.firebase.google.com/project/hitup-691be/settings/general).
3. Under **Your apps**, select the Android app (`com.posinowa.hitup`).
4. Click **Download google-services.json**.

### Step 2: Place the File
Move the downloaded file to:
```bash
android/app/google-services.json
```
*(This path is included in `.gitignore`, so it will not be committed to Git).*

### Step 3: Run the Application
```bash
flutter pub get
flutter run
```

---

## 4. Regenerating Firebase Options (FlutterFire CLI)

If project configurations change or new Firebase services are added:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=hitup-691be
```

Select Android and iOS when prompted. This command updates `lib/firebase_options.dart` and `firebase.json`.

## 5. Security & Trust Model

As documented in [`SECURITY.md`](../../SECURITY.md):
* Client configuration files (`google-services.json`, `firebase_options.dart`) are **not** privileged credentials and do not grant administrative access.
* Database security is strictly enforced by **Firestore Security Rules** (`firestore.rules` - HIT-011) and Firebase Authentication.
* **Never commit** Firebase Admin SDK service account keys (`service-account*.json`) or `.env` files with private secrets.
